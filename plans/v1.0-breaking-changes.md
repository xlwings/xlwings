# xlwings v1.0 — Breaking Changes (WIP)

## Context

xlwings has been at `0.x` for 12 years (currently 0.36.14, `Development Status :: 4 - Beta`). The v0.9.0 changelog entry from 2016 promised "only smaller changes on our way towards a stable v1.0" — that promise is a decade old. Meanwhile the codebase has accumulated 9 never-removed deprecation shims (oldest from 0.25.0), parameters for Excel 4.0 add-ins, and a set of design decisions that can only be corrected in a major version.

Two markers in the code already anticipate this release:

- [`xlwings/__init__.py:435-437`](xlwings/__init__.py#L435-L437) — *"Should be done for all constants with xlwings 1.0."*
- [`xlwings/conversion/standard.py:197-199`](xlwings/conversion/standard.py#L197-L199) — `"squeeze"` exists undocumented *"in case we want to change the default to `natural` at some point."*

The prior art is [issue #1993, "xlwings 1.0 roadmap"](https://github.com/xlwings/xlwings/issues/1993) (Aug 2022, still open, no comments). This plan is scoped to that roadmap's **Modernize / Breaking Changes / Declutter** sections, plus the code-level defects found by surveying the current tree. The roadmap's **Add Features** section is deliberately out of scope here — those are additive and don't need a major version to ship.

Two roadmap items are already done: type hints (0.34.0) and `rst` → `md` (0.36.0).

v1.0 is the one opportunity to fix things that are wrong-by-design rather than merely incomplete. After it, semver applies and these become permanent.

**Scope decisions made:** full ambition tier including the `ndim` default change; the desktop/Server split is documented rather than re-namespaced (no import churn for Lite users).

## Tier 2 — Correctness and consistency fixes

These are outright defects in the public contract.

**Getter/setter type asymmetries.** `Range.name` returns a `Name` object but accepts a `str` ([main.py:2359-2370](xlwings/main.py#L2359-L2370)) — `rng.name = "x"; rng.name` doesn't round-trip. Every other `.name` in the library is `str`↔`str`. Same class of bug: `App.cut_copy_mode` getter returns `str | None`, setter takes `bool` ([main.py:652-664](xlwings/main.py#L652-L664)).

**Unvalidated `**options`.** `Range.options()` stores its kwargs verbatim ([main.py:1961-1991](xlwings/main.py#L1961), stored at [:1885](xlwings/main.py#L1885)) with no validation, so `.options(ndmi=1)` is silently ignored and returns wrong-shaped data. Option defaults are scattered across five files with no registry. Introduce a known-option set and raise on unknown keys. Note `impl` is smuggled through the same dict ([main.py:1859](xlwings/main.py#L1859)) and must stay reserved.

**Error types.** Replace bare `Exception` with `XlwingsError` subclasses — [main.py:404](xlwings/main.py#L404), [:947](xlwings/main.py#L947), [:1078](xlwings/main.py#L1078), [:2643](xlwings/main.py#L2643), [:4320](xlwings/main.py#L4320), plus [udfs.py](xlwings/udfs.py) `:98,108,112,126,137,171,263` and [pro/udfs_officejs.py:358](xlwings/pro/udfs_officejs.py#L358). Three separate `ValueError("Invalid arguments")` sites ([:1880](xlwings/main.py#L1880), [:3051](xlwings/main.py#L3051), [:3386](xlwings/main.py#L3386)) need real messages. Two `assert`s are used for user-input validation ([:1694](xlwings/main.py#L1694), [:2693](xlwings/main.py#L2693)) and vanish under `python -O`. This also unblocks the four `# TODO: replace with specific error when Exceptions are refactored` markers in [\_xlmac.py](xlwings/_xlmac.py) (`:304,311,439,442`).

**`__eq__`/`__hash__` gaps.** `Shape`, `Table`, `Picture`, `Name` define `__eq__` without `__hash__`, making them unhashable — unusable as dict keys or in sets, unlike `Book`/`Sheet`/`Range`. `Chart`, `Font`, `Note`, `Characters`, `PageSetup` define neither. Also normalize `type(other) is X` ([main.py:799](xlwings/main.py#L799), [:4551](xlwings/main.py#L4551)) to `isinstance`.

**Dead/stale exports.** `pro/__init__.py`'s `__all__` lists `verify_execute_permission`, which does not exist anywhere — `from xlwings.pro import *` raises `AttributeError` today. `reports.py`'s `__all__` has drifted from `pro/reports/__init__.py`'s. In `xlwings.conversion`, `read`/`write`/`async_read`/`async_write` are the real entry points but aren't in `__all__`, while conditionally-imported converters are. Delete the empty `Ranges` base class ([main.py:2902](xlwings/main.py#L2902)).

**Real bugs found while surveying** (worth fixing regardless of v1.0):
- [ext/sql.py:100](xlwings/ext/sql.py#L100) — passes the builtin `type` instead of loop var `typ`, so every value is stringified. Stray `print()` at `:53`.
- [udfs.py:531](xlwings/udfs.py#L531) — `"#N/A waiting..." * count` multiplies the *string*, not a list.
- `tuple` is registered twice in the accessors dict ([standard.py:341](xlwings/conversion/standard.py#L341) and [:428](xlwings/conversion/standard.py#L428)); the second silently wins.

## Tier 3 — Design changes that need a major version

**Unify indexing.** Collections support both 0-based `[]` and 1-based `()` for the same lookup ([main.py:64](xlwings/main.py#L64) vs [:79-96](xlwings/main.py#L79-L96); same in `RangeRows`/`RangeColumns` [:2951/:2954](xlwings/main.py#L2951), `Names` [:4434](xlwings/main.py#L4434)). Two conventions on one object is the single most confusing thing in the API. Drop `__call__`-as-getter; keep `[]` 0-based.

**Fix `Apps` indexing.** `xw.apps[1668]` takes a *PID*; `xw.books[0]` takes a position ([main.py:238](xlwings/main.py#L238)). Same syntax, incompatible semantics. Make `Apps` a real `Collection` subclass with positional indexing and move PID lookup to an explicit `xw.apps.by_pid(...)`. This also removes the duplicated `count`/`__len__`/`__repr__` on `Apps`.

**Surface the constants** — the change [\_\_init\_\_.py:436](xlwings/__init__.py#L436) explicitly earmarks for 1.0. [constants.py](xlwings/constants.py) has 3,665 lines of Excel enums that the high-level API doesn't use; instead ~20 methods take magic strings (`Range.end`, `expand`, `insert`, `delete`, `copy_from`, `paste`, `autofill`, `App.calculation`, `Chart.chart_type` with ~90 values, `to_pdf(quality=)`, …). Accept real enums while continuing to accept the current strings — the enums are the documented path, strings stay working. This is the one Tier 3 item that need not break anything.

**Normalize `to_pdf`.** Four different signatures across `Book` ([:1249](xlwings/main.py#L1249)), `Sheet` ([:1604](xlwings/main.py#L1604)), `Range` ([:2853](xlwings/main.py#L2853)), `Chart` ([:3949](xlwings/main.py#L3949)) — `show` defaults to `False` in two and `None` in the others; `layout` is missing on `Chart`.

**Rename `Range.autofill(type_=)`** ([main.py:2880](xlwings/main.py#L2880)) — the only trailing-underscore parameter in the public API.

**Constant naming** (roadmap). Beyond surfacing the enums, drop the leading `xl` and switch to snake_case — `xlCalculationManual` → `calculation.manual`. This is the difference between exposing VBA's names and exposing xlwings' own; worth doing in the same pass as the enum work rather than twice.

**Integers as ints, not floats** (roadmap). Every engine except pywin32 and appscript already returns real ints; those two return floats for whole numbers. Normalizing means `sheet["A1"].value` returns `1` instead of `1.0` on desktop. Like Tier 4, this changes values silently rather than raising — but the blast radius is far smaller (it fixes an inconsistency users already work around), and it makes desktop match Server/Reader, which is a correctness win rather than a taste call.

**Settings naming** (roadmap). Config keys are inconsistently spaced vs. underscored — `INTERPRETER_WIN` and `ADD_WORKBOOK_TO_PYTHONPATH` but `"CONDA PATH"`, `"UDF MODULES"`, `"DEBUG UDFS"`, `"SHOW CONSOLE"`. Standardize on `_`. This touches the VBA side ([addin/Config.bas](xlwings/addin/Config.bas)) as well as Python, and needs a compatibility window that accepts both spellings, since config lives in users' workbooks and `xlwings.conf` files rather than in their code — they can't fix it with a find-and-replace on a repo.

## Tier 3b — Roadmap items needing a design decision first

These are from #1993 and are larger than the mechanical changes above. Each needs its API settled before implementation, and each could reasonably slip to a later release.

**Converter refactor.** The roadmap's proposal, motivated by converters not playing nicely with type hints:

```python
myrange.value                     # list of lists
myrange.options(numbers=int).value
myrange.to_pd()                   # pandas DataFrame
myrange.to_pd(index_col=0)
myrange.to_pl()                   # polars
```

This directly addresses the untyped `**options` bag in Tier 2 — `to_pd(index_col=0)` can be typed and IDE-completed in a way `options(pd.DataFrame, index=1)` never can. The roadmap notes current behavior could remain supported for backward compatibility, which makes it additive-then-deprecate rather than a hard break. Worth pairing with the Tier 2 option-validation work so the two don't conflict.

**pandas alignment.** Align DataFrame reading with pandas: replace `index=1` with `index_col`. Currently `index`/`header` take integers-as-counts ([pandas_conv.py:86-87](xlwings/conversion/pandas_conv.py#L86-L87)) which reads like pandas' API but doesn't mean the same thing. The roadmap leaves the column-header default open — that's the sub-decision to settle.

**Replace `Book.caller()`** with parameter injection — `def myfunc(book: xw.Book):`. This is already how xlwings Server works, so it unifies the two programming models rather than inventing anything. It also removes the `set_mock_caller()` testing dance ([main.py:1083](xlwings/main.py#L1083)). Big change for every existing `RunPython` script, and the quickstart template plus all the docs move with it.

**0 vs 1-based indexing, decided and documented.** Tier 3 above removes the `()` 1-based *accessor*; this is the separate question of what `.index` returns. The roadmap notes Office Scripts and Google Apps Script chose differently (0 vs 1), and floats a nice non-breaking option: follow Jinja2 with both `.index` and `.index0`. That sidesteps the break entirely and is worth preferring over changing `.index`.

**`pip install "xlwings[standard]"`** for default deps. Makes it possible to install without pywin32/appscript for editable installs. Breaks the plain `pip install xlwings` expectation on desktop, so it needs prominent release-note placement — this is the kind of change that generates issue traffic no matter how well documented.

**Docstring-parsed argument help.** Replace `@arg(doc="...")` with parsing the function's docstring (Google/NumPy style). Additive and non-breaking; listed here because it's the roadmap item most likely to improve day-to-day UDF authoring.

**Vector orientation.** The roadmap raises whether to follow PiE in returning vectors vertically, then argues against it — horizontal matches the Excel layout when you take a row out of a 2-D block. I'd leave this as-is; it's noted for completeness, and it interacts with Tier 4, so if `ndim` changes this should stay fixed to avoid two orientation changes landing at once.

## Tier 4 — The `ndim` default change

**This is the highest-risk item in the plan and should be decided independently of everything above.**

Today a single-column range squeezes to 1-D:

```python
sheet["A1:A3"].value    # now:  [1, 2, 3]
                        # v1.0: [[1], [2], [3]]
```

This is roadmap item *"Switch `ndim` from the current behavior to `ndim="natural"`, which leaves columns in 2d notation. The previous behavior can be activated via `ndim="squeeze"`."* — so both the target and the opt-out are already decided; `"squeeze"` is the documented escape hatch.

The machinery already exists: `ndim="natural"` ([standard.py:215-226](xlwings/conversion/standard.py#L215-L226), added 0.33.19) and the currently-undocumented `"squeeze"` alias, added specifically to preserve today's behavior if the default ever moved ([standard.py:197-199](xlwings/conversion/standard.py#L197-L199)). Implementation is therefore small: flip the default, document `"squeeze"`.

The argument for it: the current default is genuinely surprising — a 3×1 range and a 1×3 range both read as a flat list, losing orientation, and code written against a multi-column range silently breaks when the data narrows to one column.

**Why it still needs separate consideration:** every other change in this plan fails loudly. This one fails *silently*. Existing scripts that read a column and iterate over it keep running and produce wrong results — no exception, no warning. It can't be shimmed with a `DeprecationWarning`, because both old and new behavior are valid returns. The blast radius is every script that reads a single column or row, which is a large share of real xlwings usage. Low implementation cost and low user cost are different things, and only the first one is settled.

Recommended mitigations:
1. In the final 0.x release, emit a warning whenever a read *would* differ under `"natural"` — i.e. when the result is squeezed from N×1. This is the only way users get a signal, and it's silenced by passing `ndim=` explicitly.
2. Document `"squeeze"` as a supported public value **before** the switch, not as part of it, so there's a documented target to migrate to rather than one that appears the day the default changes.
3. Lead the release notes with this, not with the deprecation removals.

If the warning pass in step 1 fires on a large fraction of real workbooks, that's the signal to defer to v2.0 and ship the rest as v1.0.

**Note on interaction:** the "integers as ints" change in Tier 3 has the same silent-failure property. If both ship in one release, a single read can change in two ways at once — shape *and* type. Consider staging them across releases, or at minimum making the step-1 warning cover both.

## Tier 5 — Document the desktop/Server split

Per the scoping decision: no code moves, no import changes. `xw.WithScript`, `xw.ObjectHandle`, `xw.CachedObject`, `xw.BookAsync`, `xw.CustomFunctionResult` stay top-level.

What changes is that the split becomes *legible*:

- Mark Lite/Server-only members in docstrings and typing: the async `get_*` family ([App.get_selection:378](xlwings/main.py#L378), [Book.get_selection:1239](xlwings/main.py#L1239), [Books.get_active:4922](xlwings/main.py#L4922), [Sheets.get_active:5034](xlwings/main.py#L5034), [Range.get_value:2427](xlwings/main.py#L2427)), `Book.load`/`Sheet.load`, `Book.flush`, and `BookAsync` (a runtime no-op marker class, [main.py:1357](xlwings/main.py#L1357)).
- **Make the no-op UDF decorators raise.** On macOS/Linux desktop, `@xw.func` currently resolves to a silent passthrough ([\_\_init\_\_.py:358-423](xlwings/__init__.py#L358-L423)) — it does nothing and reports nothing. Raise a clear `XlwingsError` naming the requirement instead. This is the worst silent failure in the library.
- **Validate decorator kwargs.** `xw.func` accepts disjoint kwargs per platform (`category`/`call_in_wizard`/`async_mode` on Windows; `name`/`namespace`/`help_url`/`required_roles` on Office.js) and neither implementation rejects unknown ones — `@xw.func(volatil=True)` is a silent no-op on both.
- Add API-reference pages for the ~12 public names that have none (`Macro`, `FreezePanes`, `Engine`/`Engines`, `ObjectHandle`, `WithScript`, `CachedObject`, `to_datetime`, …). The reference is currently 100% autodoc stubs, and the top-level page documents only `view` and `load`.

## Tier 6 — Declutter (removals)

Straight from the roadmap's Declutter section. Each of these is a whole subsystem, so removing them is the highest-leverage maintenance win in the plan.

- **Remove the REST API** ([`xlwings/rest/`](xlwings/rest/)). This settles the open question I'd flagged: it's GET-only, Flask-dev-server-only, effectively undocumented (one line in `command_line.md`), and untouched since 2023. Shipping 1.0 with it would commit to it under semver. Removing it also drops the `restapi run` CLI command and `tests/restapi/`.
- **Remove support for other Office apps** (Access etc.) — already marked *"experimental and may be removed in the future"* in [docs/other_office_apps.md:6](docs/other_office_apps.md#L6).
- **Remove round-parenthesis indexing** — this is Tier 3's indexing change, and the roadmap gives the rationale I'd argue for independently: *"There should be one-- and preferably only one --obvious way to do it."*
- **Remove legacy dynamic-array support** in Windows UDFs — currently kept alive by the `gencache.EnsureModule` block wrapped in a bare `except:` ([\_\_init\_\_.py:344-357](xlwings/__init__.py#L344-L357)), which also mentions the `caller` argument. Removing this is what makes that block deletable.

Related cleanup this enables: the legacy Fernet license-key path ([pro/utils.py:84-90](xlwings/pro/utils.py#L84-L90), pre-0.27.12) is a second full code path in `validate_license` and `create_deploy_key` that can go at the same time.

## Tier 7 — Refactors (non-breaking, but v1.0-shaped)

From the roadmap's Refactor section. None of these change the API, but all are easier to do *with* the breaking changes than after.

- **Split `main.py` (5,141 LOC) and `cli.py` (1,309 LOC) into modules.** Doing this in the same release as the removals means one big diff instead of two.
- **Refactor the tests to pytest and make them fast.** See Verification below — this is a prerequisite, not a nice-to-have.
- **Finish `setup.py` → `pyproject.toml`.** Blocked on relocating the DLLs (they currently ship as `data_files` next to `python.exe`); the roadmap notes they shouldn't have to live there anymore.

- **Metadata**: bump `Development Status` to `5 - Production/Stable`. `requires-python = ">=3.9"` but CI floors at 3.10 — align them. No 3.14 classifier despite 3.14 support. `setup.py` and `pyproject.toml` extras have drifted (`anyio` missing from one, `pytest` listed twice in the other).

## Sequencing

The scope here is now large enough that it won't land in one release. Suggested split:

1. **0.37.0 — the warning release.** Add proper `DeprecationWarning`s to every Tier 1 item (especially the four currently-silent ones), the Tier 4 ndim-divergence warning, and the int/float warning if that ships. Document `"squeeze"`. Change no behavior. Let it sit for a release cycle or two.
2. **Additive work, any time before 1.0.** The non-breaking items don't need to wait: enums accepted alongside strings, `.index0`, docstring-parsed arg help, and the `to_pd()`/`to_pl()` converter API added next to the existing one. Shipping these early means users can migrate *before* the breaking release rather than during it.
3. **Evaluate.** Use the step-1 warning signal to make the final `ndim` call.
4. **1.0.0.** Remove Tier 1 and Tier 6, apply Tiers 2, 3, 5, and Tier 4 if confirmed. Tier 7's refactors ride along here.
5. **Deferred.** Tier 3b's larger items (`Book.caller()` replacement, pandas `index_col` alignment, `[standard]` extra) each need their API settled first — if any isn't ready, it slips rather than holding the release.

The ordering principle: everything that can be additive should ship before 1.0, so that 1.0 itself is mostly *removals* of things already deprecated with warnings. That's the difference between a migration users can do incrementally and one they have to do all at once.

## Verification

The full test suite is reported broken in `DEVELOPER_GUIDE.md` ("recommended to run single modules instead") — **fix that first**, or none of the below is trustworthy.

- Per-module runs against a live Excel: `tests/test_range.py` (884 LOC), `test_book.py`, `test_sheet.py`, `test_app.py`, `test_conversion.py` (649 LOC), `test_ndim.py`.
- `test_ndim.py` and `test_conversion.py` are the gate for Tier 4 — expect substantial rewrites there, and treat the size of that diff as itself a signal about user impact.
- Coverage gaps to close before relying on the suite for a 1.0 sign-off: there is **no** `test_chart.py`, `test_picture.py`, `test_note.py`, `test_macro.py`, `test_freeze_panes.py`, or `test_cli.py`. The CLI (1,309 LOC, 14 subcommands) has zero dedicated tests, and Tier 1/Tier 5 both touch it.
- Type-checking: `[tool.pyright]` excludes `_xlwindows.py`, `_xlmac.py`, `conversion/**`, `pro/**`, `rest/**`, `cli.py` — so the "fully type-hinted public API" is verified only on the facade. Tier 2's typing fixes should come with widening that include list.
- Manual smoke test on both platforms: `xlwings quickstart`, the `Run main` button, a `RunPython` round-trip, and a UDF on Windows.
